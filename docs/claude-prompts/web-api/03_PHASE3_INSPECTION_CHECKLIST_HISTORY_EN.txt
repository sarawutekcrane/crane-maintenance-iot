IMPORTANT:

1. The browser must never read/write Google Sheets directly.
2. The Web must call the Backend API.
3. ESP32 devices must call the Backend/Device API, not Google Sheets.
4. Business logic belongs in backend/domain services, not spreadsheet formulas.
5. The repository layer isolates Google Sheets from business logic.
6. Replacing Google Sheets with PostgreSQL later must not require rewriting Web workflows.
7. API contracts must be versioned and stable.
8. Historical records must not be overwritten.
9. Revision-controlled masters must preserve old historical meaning.
10. Do not fabricate missing real-world data.

QR RULE
======================================================================

One crane must have ONE permanent QR code.

QR target:

/vehicle/{vehicle_id}

The QR opens Vehicle Detail, not a dedicated inspection-only page.

Workshop equipment may use:

/equipment/{equipment_id}

and one permanent QR per machine.

OBJECTIVE

Implement simple QR-based daily/weekly inspection for vehicles and workshop equipment.

USER FLOW

Scan QR
-> Detail page
-> ตรวจเช็ค
-> Complete checklist
-> ส่งผลการตรวจ

SCOPE

A. Revision-controlled checklist master.

Each item may include:
- inspection title
- inspection point
- reference image
- inspection method
- acceptance standard
- instruction
- frequency
- display order
- photo requirement
- active status.

B. Server automatically chooses the correct effective checklist revision.

C. Thai inspection UI:
- หัวข้อที่ตรวจ
- จุดที่ตรวจ
- รูปจุดตรวจ
- วิธีการตรวจ
- มาตรฐานการตรวจ
- คำแนะนำ
- ผ่าน
- ไม่ผ่าน
- ไม่เกี่ยวข้อง
- หมายเหตุ
- แนบรูปผลตรวจ.

D. Keep Reference Image separate from Inspection Photo.

E. Inspection header/result:
asset
checklist revision
inspector
timestamp
counter snapshot when available
each item result
remark
attachments.

F. Inspection history is immutable.

G. FAIL behavior:
- create abnormal finding/maintenance review item by default,
- critical rules may trigger alert/repair workflow,
- do not create excessive repair orders automatically.

H. APIs:
current checklist
create inspection session
submit results
history
detail
finding.

ACCEPTANCE TESTS

1. QR -> Detail -> inspection is simple.
2. Correct checklist loads automatically.
3. Thai UI renders instructions.
4. PASS/FAIL/N/A save correctly.
5. required FAIL remark/photo works.
6. reference image is separate from evidence.
7. submitted inspection becomes history.
8. old inspection keeps old checklist revision.
9. FAIL can create a finding.
10. critical rule can use defined alert/repair path.
11. workshop equipment uses the same generic inspection engine.

EXIT GATE

Inspection is usable by ordinary staff without database knowledge.
