OBJECTIVE
=========

Implement OTA management and the Backend/Web framework required for a future approved model-specific emergency output.

SCOPE
=====

OTA release:
- firmware version
- hardware compatibility
- channel
- checksum
- signature metadata
- storage_ref
- status.

Deployment:
DEV
PILOT
GROUP
FLEET

Track target/progress/result/failure.

Firmware binary is external storage, not database cell content.

Safety-critical command:
separate from normal commands.

Future example:
REMOTE_INHIBIT

Safety request must support:

- exact target vehicle/device
- model
- current online state
- engine/PTO state if available
- last seen
- GPS if available
- reason
- short TTL
- explicit confirmation
- MFA/step-up integration point
- command ID
- ACK
- execution state
- physical feedback state
- audit context.

Stale command protection is mandatory.

Emergency profile metadata may store:

- profile ID
- model ID
- revision
- compatibility
- approval status.

Ordinary Web users must not freely edit individual fixed ON/OFF timing values.

Physical feedback is separate from output activation.

Do not label as certified E-Stop without complete engineered safety qualification.

ACCEPTANCE TESTS
================

- OTA metadata/deployment works
- binary remains external
- incompatible release can be rejected
- safety domain is separate
- TTL required
- stale command cannot remain executable
- exact target/model shown
- reason required
- command states distinct
- feedback state distinct
- timing values are not ordinary editable config
- audit context exists.

EXIT GATE
=========

Backend/Web is ready for approved ESP32 emergency profiles without redesign.
